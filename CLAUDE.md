# AOMarkup – notes for Claude

AOMarkup (`nadybot/aomarkup`, namespace `AO\Markup`, AGPL-3.0-or-later) is a bot-agnostic
library: it parses **AoXML** into a document tree and exports it to AOML (official client),
lepanel (Lost Eden), ANSI, plain text, HTML and Discord. Its first consumer is Nadybot
(`~/bot/Nadybot`), which today converts its BBML with regexes in five places
(`Core/Text.php`, `Core/Blob.php`, `CONSOLE/ConsoleCommandReply.php`,
`WEBSERVER_MODULE/WebChatConverter.php`, `DISCORD/DiscordController.php`).
Sister package: `nadybot/aolib` (namespace `AO\`, the chat client).

Read first: `docs/AoXML.md`, `docs/Architecture.md`, `tests/Samples/README.md`
(`docs/LePanel.md` for Lost Eden).

## Ground rules (decided)
- The document tree is the contract; AoXML is only its text form. The library knows
  nothing about a specific bot; bot-specific things come in through `RenderContext`
  (Theme, PlaceholderProvider, LinkResolver, PSR-3 logger).
- AoXML is our own format, tailored to our needs (e.g. pagination hints: `<pagebreak>`,
  `<keep>`, `<repeat>`), not a copy of any target format.
- Strict closing: `</green>` instead of `<end>`; `<tr>`, `<td>`, `<th>`, `<li>` are always closed.
  Only known void tags may omit the slash.
- No `<tab>`, no `<black>` padding, no layout with spaces in AoXML. Use `<section>`, `<dl>`,
  `<table>`, `<ul>`/`<ol>`, `<indent>`. Leading whitespace in the source is not significant.
- Game objects are semantic elements (`<item>`, `<nano>`, `<skill>`, `<char>`, `<waypoint>`,
  `<cmd>`, `<client>`, `<url>`). AoXML has no `<a>`.
- Emphasis is `<strong>`, not `<highlight>` (the theme colour is still called highlight).
- Attribute values are always plain text; placeholders only exist as elements in content.
  Bot commands through a channel use `<cmd via="priv|org">`.
- Windows are defined at the top level (`<window id title>`) and opened with
  `<popup window="id">link text</popup>` from the message only. No nesting, no window names.
  In the tree they are `Document::$windows`, like the format Nadybot sends to its web client.
- BBML (Budabot markup: `<highlight>`, `<end>`, `<tab>`, …) is not AOML. Funcom AOML is a
  subset of BBML; both are read by `BbmlImporter`, not by `AoXmlParser`. Colours are never
  guessed back into semantic styles.
- Export targets for the game: `AomlExporter` (colours resolved; client and foreign relays such as
  GrcV2) and `BbmlExporter` (named styles kept, placeholders resolved; relays to bots that
  apply their own theme, e.g. NadyNative to older Nadybots).
- Relays never carry lepanel markup.
- Importers never produce widgets, and never guess structure: `BbmlImporter` translates literally
  but cleanly (`docs/AoXML.md` §6); each sample's `expected-import.aoxml` is its spec. Guessing is
  only allowed as an explicit option (`detectTables`, `detectLists`, §6.1/§6.2, spec:
  `expected-detected.aoxml`); with them, samples without tables or lists must still give
  `expected-import.aoxml`.
- Closing notes of a window (credits, legends, sources) are `<footer>`, never a guessed
  "last paragraph".
- `<choice command>` with `<option value selected?>` is a widget (fallback: list with `[select]`
  links; native: HTML `<select>`, Discord select menu). `<match>`/`<selected>` stay inline styles.
- `<pagebreak/>` is a possible break, never a forced one: if a window has any, pages end only
  there, and only where needed (`docs/AoXML.md` §2.2).
- Boolean attributes: `<table border>` is allowed as input; canonical form is `border="true"`.
- Table alignment: `<th align>` is the default for its column, `<td align>` overrides it.
  No `columns` attribute. Details in `docs/AoXML.md` §2.1.
- AOML/BBML exporters pad numeric cells and field values (only digits, `.`, `,`) with black `0`s
  (8 px, like every digit), the rest with spaces; detected when rendering, not marked in AoXML.
- The list bullet is an exporter option (`-` for AOML, `•` for ANSI/plain text).
- The slider bar uses the narrowest of `|` and `l` in the target metric: `l` in the AO font
  (4 px, looks much better than `|`), `|` in monospace.
- Items: `<item id="low/high" ql="…">` (or `id="low"` if low = high). No `ref` short form;
  AoXML is mostly generated by code, so explicit beats short.
- **No exceptions in renderers:** even one-off things like the agg/def bar are widgets.
  A widget is one class with constructor parameters as attributes and a mandatory
  `fallback()` that returns core nodes only; native renderers per exporter are optional.
- The `expected.*` files in `tests/Samples` are the specification. Change them first,
  then make the code follow.
- PHP `>=8.1.17` (no readonly classes), no I/O, errors as PSR-3 warnings instead of exceptions.

## Open questions
- lepanel: the Lost Eden developers described their tags on 2026-11-27 (`docs/LePanel.md`).
  There are no tables and no inline formatting (bold, colours, links in text) yet; the
  `expected.lepanel` files predate this and must be rewritten with the real tags before
  `LePanelExporter` is built. Open questions for them are listed in `docs/LePanel.md`.

## Conventions
- Code, comments, docs and commit messages in English.
- Never add a `Co-Authored-By` trailer to commit messages.
- Checks: `composer tests` (PHPUnit, PHPStan level 8, phpcs, mago if installed);
  style via `vendor/bin/php-cs-fixer.phar fix`.
- `bin/show-sample <sample> [ansi|txt|aoml|bbml|lepanel|html|discord.json|aoxml|legacy]` shows a sample.
- `bin/font-calibration` prints test popups to measure the client font (`docs/FontCalibration.md`).
